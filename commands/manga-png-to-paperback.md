CanvaなどでエクスポートしたPNGファイルを、Kindle KDP入稿用のPDFに変換する。

## 実行方法

すべての質問を **AskUserQuestion（選択式ダイアログ）** で行う。テキストで聞かない。

### ステップ1：フォルダパスを確認する
AskUserQuestion でフォルダパスを聞く。

### ステップ2：基本設定をまとめて聞く
以下の2つを1回のAskUserQuestionで聞く：
- 判型（A5 / B6）
- ノンブル（あり / なし）

**裁ち落とし・余白の追加はここでは聞かない。** ステップ3で実際の画像を測って自動判定する（詳細は後述）。

### ステップ3：余白のチェック（裁ち落とし・余白追加の要否を自動判定）

**この判断は必ずノンブルを追加する前に済ませる。** ノンブルの表示位置は塗り足し（トリム線）からの固定距離で決まるため、ノンブルを入れた後にページをトリミングすると、ノンブルがKDPの規定マージンより外側（トリム線に近すぎる位置）にはみ出し、入稿審査に通らない恐れがある。順序は **トリミング／余白方式の確定 → ノンブル追加** を厳守する。

**チェックに時間をかけすぎない。** 全PNGの measurement は1回のPythonループにまとめ、複数回に分けて実行しない。開始前に「余白をチェックしています」のように、今何をしているか一言テキストで伝えてから実行する（無言で進めない）。

0. KDPの必要最低余白（[公式ガイド](https://kdp.amazon.com/en_US/help/topic/GVBQ3CMEQW3W2VL6)基準）：
   - 外側3辺（天・地・小口）：6.4mm未満なら不足
   - のど（綴じ側）：ページ数で変わる（24–150p=9.6mm／151–300p=12.7mm／301–500p=15.9mm／501–700p=19.1mm／701–828p=22.3mm）
   - AIマンガは単ページ書き出しでどちらが綴じ側か判別できないことが多いため、左右どちらも暫定的に外側基準（6.4mm）で判定してよい（正確なのど判定が必要な案件では別途確認する）
1. 全PNGファイルを1回のPythonループで自動チェックする：各画像の非白ピクセルの外接矩形を検出し、上下左右それぞれの余白をpx→mm換算する（判型のmmサイズと画像pxサイズから算出）。数百枚でも一括で数秒以内に終わるため、ユーザーに確認は取らない。
2. 全ページが基準を満たしていれば、何も聞かずそのまま「裁ち落としなし・余白追加なし」で進める。一言だけ結果を報告する（例:「余白チェックをしています」→「全ページ余白は十分だったので、このまま進めます」）。
3. 基準未満のページがあれば、該当ページと不足辺・実測値を簡潔に報告し（例:「004.png、右端の余白が2.1mmでした（基準6.4mm）」）、AskUserQuestionで2択を聞く：
   - 「10mmの余白をつける」— 絵は意図せず端に寄っているだけの場合
   - 「裁ち落としあり」— 絵を意図的に端まで届かせているデザインの場合
4a. 「10mmの余白をつける」を選んだ場合：余白追加=y、裁ち落としなしで進める。
4b. 「裁ち落としあり」を選んだ場合：`manga_pdf_maker.py` 本体は書き換えず、スクラッチパッドにコピーして該当箇所（余白なし分岐の `scale = min(...)` を `scale = max(...)`）だけを直した一時スクリプトを用意する。ページサイズ（判型＋塗り足し）は変えず、画像側だけ拡大してはみ出しをトリミングする。
5. この時点で方式を確定させてから、ステップ4に進んでノンブルを含めた最終生成を行う（画像とノンブルは常に同じスクリプト実行の中で一緒に生成し、完成後のPDFを後から crop するようなことはしない）

### ステップ4：ノンブル開始ページ・非表示ページ（ノンブルありの場合のみ）
以下の2つを1回のAskUserQuestionで聞く：
- 1ページ目をどの画像から始めるか（ファイル名の数字部分、例: 001）。**指定した画像が印字上の「1」になる**（印字される番号は常にそこから1,2,3…と連番になり、ファイル名の数字とは無関係。例えば「005」を指定しても005.pngに印字されるのは「5」ではなく「1」）
- ノンブルを表示させたくないページ（表紙・扉・章扉など。ドット区切り、例: 001.024.059。なければ「なし」）※内部的には「スキップページ」と呼ぶ機能だが、ユーザーには「スキップ」ではなく必ず「ノンブルを表示させたくないページ」と聞く（「スキップ」は誤解を招く表現のため使わない）

**強制白抜きページはこの時点では聞かない。** どのページが自動判定で白抜きミスしそうかは、実物のPDFを見るまで正確に決められないため。まず強制白抜きなし（自動の局所明度判定のみ）で生成し、ステップ6の完了後チェックで実際の出力を見てから、ユーザーの追加指示を受けて必要なら再生成する（詳細はステップ6参照）。なお「ノンブルを表示させたくないページ」もここで聞いた後、目視して追加に気づくことがあるため、ステップ6でも重ねて確認する。

### ステップ5：スクリプトを実行する

スクリプトは対話式（`input()`で質問してくる）なので、**そのまま実行するとハングする**。
フォルダパスは第1引数で渡し、質問への回答は集めた内容から **printf で stdin に流し込む**：

```bash
printf '<判型>\n<裁ち落とし>\n<ノンブル>\n<開始ページ>\n<スキップ>\n<白抜き>\n<余白y/n>\n' \
  | python3 ~/my-workspace/manga_pdf_maker.py "<フォルダの絶対パス>"
```

質問の順序（この順で1行ずつ回答する）：

1. 判型 … `A5` または `B6`（表記そのまま。小文字は不可）
2. 裁ち落とし … `あり` または `なし`
3. ノンブル … `あり` または `なし`
4. ノンブル開始ページ（例: `001`）… **ノンブル「あり」の場合のみ**
5. ノンブルを表示させたくないページ（例: `001.024.059`、なければ空行）… 同上。ステップ4で聞いた内容を入れる
6. 強制白抜きページ（例: `005.010`、なければ空行）… 同上。**初回生成は空行のまま実行する**（ステップ6で追加指示があれば、その時点でここに入れて再実行する）
7. 余白の追加 … `y`（余白なし画像）または `n`（余白あり画像）

**ノンブル「なし」の場合は4〜6の行を入れない**（4行だけ流す）：

```bash
printf 'A5\nなし\nなし\ny\n' | python3 ~/my-workspace/manga_pdf_maker.py "/path/to/folder"
```

出力PDFはフォルダの**親ディレクトリ**に `KDP_<判型>_<裁ち落とし>...pdf` の名前で保存される。実行後にそのパスをユーザーに伝える。

ステップ3で「裁ち落としあり」を選んだ場合は、上記の標準スクリプトではなく、ステップ3-4bで用意した一時スクリプト（`scale = max(...)` に直したもの）を同じ引数・同じ質問順で実行する。標準スクリプトと一時スクリプトを混在させたり、生成済みPDFを後からトリミングしたりしない。

## 注意事項

- `manga_pdf_maker.py` が見つからない場合は `install.sh` を再実行するよう伝える
- PNGファイルは 001.png、002.png のように連番にする必要がある
- ノンブルを表示させたくないページ・白抜きページはファイル名（拡張子なし）をドット区切りで指定する
- 暗いページのノンブルは自動で白抜きになる（ページ全体の平均明度ではなく、ノンブルが乗る位置周辺の局所明度で判定する）

## 完了後チェック（アドボケート検証）

スクリプトの実行が終わったら、検証結果を伝える前にまず「できました。検証に入ります」など一言だけ状況をテキストで伝える（無言で検証を続けない。ユーザーが待てるように、今何をしているかの一言を挟む）。

その後、出力PDFのパスをユーザーに伝える前に、以下を確認する。**検証は下記チェック項目をまとめて1回で行い、細切れに何度も検証を繰り返さない**（ページ数一致・判型サイズ・ノンブル反映等は1つのPythonスクリプトにまとめる。目視確認も対象を絞って一括で見る。詳細は本セクション末尾を参照）。

- [ ] 選んだ判型（A5/B6）が正しくPDFに反映されているか（ステップ2の回答と出力ファイル名の`KDP_<判型>_...`が一致しているか）
- [ ] 出力PDFの総ページ数が入力PNGファイル数と一致しているか
- [ ] ステップ3で余白不足が検出されていた場合、採用した方式（余白10mm追加 / 裁ち落とし＋トリミング）通りに仕上がっているか、該当ページを画像化して四辺を確認する
- [ ] トリミングを行った場合、ノンブルが上下端で切れていない・トリム線に寄りすぎていないかを画像化して目視確認する

不一致や不安な点があれば、パスを伝える前にユーザーに一言添える（例：「◯ページ目、白抜き指定が反映されているか念のためご確認ください」）。

### 完成後の「修正したい箇所はありますか？」確認

上記チェックが済んだら、出力PDFのパスを伝えると同時に必ず「修正したい箇所はありますか？」と一言添える（狭く「ノンブルを表示させたくないページは？」「白抜きページは？」のように個別に聞かない。ステップ4で答えた「ノンブルを表示させたくないページ」への追加、白抜き判定が期待と違うページ、その他気づいた点をまとめて拾うための、あえて広い聞き方にする。ユーザーは初回は速さ優先で細かい指定を省略・見落としがちなので、実物を見てから思い出す前提で聞く）。

ユーザーから指定があった場合：
1. 「ノンブルを表示させたくないページ」の追加分・強制白抜き指定として整理する（ステップ4で既に答えている分があれば、それに追加する形でまとめる）。両方にまたがるファイル名がないか確認する（ノンブルを表示させたくないページに指定されたページはノンブル自体が描画されないため、白抜き指定をしても無効になる）。重複があれば強制白抜きリストから外し、「◯◯は非表示指定と重なっていたため白抜き指定から外しました」と伝える。
2. ステップ5の printf コマンドの該当行（ノンブルを表示させたくないページ／強制白抜き）だけを更新し、他の回答はそのまま**同じ設定で再実行**する（判型・裁ち落とし・開始ページ等を聞き直さない）。
3. 再実行後は出力PDFが上書きされるので、そのパスを改めて伝え、再度「修正したい箇所はありますか？」と確認する（解消するまで繰り返す）。ページ数一致等も再度確認する。

指定がなければそのまま完了とする。

**検証は1回のPythonスクリプトにまとめて実行する。** ページ数一致・判型サイズ・ノンブルのスキップ/白抜き反映（テキスト抽出で判定可能）は、Pythonプロセスを都度立ち上げ直さず、1つのスクリプト内でまとめて確認する。画像化して目視確認するのは、白フチ・トリミング・ノンブルの位置関係など「実際に見ないと判断できない」項目に限定し、合計1〜2ページ程度に絞る（Readツールでの画像読み込みも同数に抑える）。細切れの検証を繰り返すと応答が遅くなる。

## フォルダパスがわからない場合

**Mac:** Finderでフォルダを右クリックし、**Optionキーを押しながら**「パス名をコピー」を選ぶ。

**Windows:** エクスプローラーでフォルダを**Shiftキーを押しながら右クリック**し、「パスのコピー」を選ぶ。

コピーしたパスをチャットに貼り付けてもらう。
