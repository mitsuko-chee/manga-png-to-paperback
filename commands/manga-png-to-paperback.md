CanvaなどでエクスポートしたPNGファイルを、Kindle KDP入稿用のPDFに変換する。

## 実行方法

すべての質問を **AskUserQuestion（選択式ダイアログ）** で行う。テキストで聞かない。

### ステップ1：フォルダパスを確認する
AskUserQuestion でフォルダパスを聞く。

### ステップ2：基本設定をまとめて聞く
以下の4つを1回のAskUserQuestionで聞く：
- 判型（A5 / B6）
- 裁ち落とし（あり / なし）
- ノンブル（あり / なし）
- 余白の追加（y=余白なし画像 / n=余白あり画像）

**「裁ち落とし：あり」を選んだ場合、以下の警告をテキストで表示する：**
> ⚠️ 注意：「裁ち落としあり」は塗り足し（3mm）付きのテンプレートで作った画像専用です。

### ステップ3：白フチのチェック（トリミングが必要か判断）

**この判断は必ずノンブルを追加する前に済ませる。** ノンブルの表示位置は塗り足し（トリム線）からの固定距離で決まるため、ノンブルを入れた後にページをトリミングすると、ノンブルがKDPの規定マージンより外側（トリム線に近すぎる位置）にはみ出し、入稿審査に通らない恐れがある。順序は **トリミング（画像の拡大縮小方式の確定）→ ノンブル追加** を厳守する。

1. 「余白の追加：n」を選んだ場合、PNG画像の縦横比と判型（塗り足し込み）の縦横比を比較する（画像サイズは基本的に全ページ共通なので1枚チェックすれば足りる）
2. ズレがあり、はみ出さない方向（contain）で縮小すると白いフチが出ると分かった場合：
   a. まず実際の白フチの大きさ（mm換算、片側あたり）をテキストで一言報告する（例:「左右に約0.9mmずつ白フチが出る可能性があります」）。scale_w = page_w/img_w, scale_h = page_h/img_h を計算し、小さい方が制約辺、余った側の (page辺 - scaled辺) がフチ幅。
   b. その上で AskUserQuestion で3択を提示する。KDPの断裁には数mm程度のブレが実際にあるため、フチが片側1mm未満なら断裁時にほぼ吸収されて目立たない可能性が高い→「このまま進める（contain）」を1番目（推奨）にする。片側1mm以上なら断裁のブレを考慮しても肉眼で分かるフチになりやすい→「拡大トリミング（cover）に切り替える」を1番目（推奨）にする：
      - 「このまま進める（contain）」— 誤差がKDPの裁断誤差許容内に収まりそうな場合
      - 「全ページ一括で拡大トリミング（cover）に切り替える」— フチが目立つ場合
      - 「特定ページのみ直す」— 選ばれたら、どのページ番号かをこの後のチャットで確認し、該当ページだけ個別に画像を編集する（一括のscale変更はしない）
3. トリミング（cover）を採用する場合は `manga_pdf_maker.py` 本体は書き換えず、スクラッチパッドにコピーして該当箇所（余白なし分岐の `scale = min(...)` を `scale = max(...)`）だけを直した一時スクリプトを用意する。ページサイズ（判型＋塗り足し）は変えず、画像側だけ拡大してはみ出しをトリミングする
4. この時点でトリミング方式を確定させてから、ステップ4に進んでノンブルを含めた最終生成を行う（画像とノンブルは常に同じスクリプト実行の中で一緒に生成し、完成後のPDFを後から crop するようなことはしない）

### ステップ4：ノンブル詳細（ノンブルありの場合のみ）
以下の3つを1回のAskUserQuestionで聞く：
- ノンブル開始ページ（ファイル名の数字部分、例: 001）
- スキップするページ（ドット区切り、例: 001.024.059。なければ「なし」）
- 強制的に白抜きにしたい特定ページ（ドット区切り、例: 005.010。なければ「なし」）

### ステップ5：スクリプトを実行する

スクリプトは対話式（`input()`で質問してくる）なので、**そのまま実行するとハングする**。
フォルダパスは第1引数で渡し、質問への回答は集めた内容から **printf で stdin に流し込む**：

```bash
printf '<判型>\n<裁ち落とし>\n<ノンブル>\n<開始ページ>\n<スキップ>\n<白抜き>\n<余白y/n>\n' \
  | python3 ~/my-workspace/manga_pdf_maker.py "<フォルダの絶対パス>"
```

質問の順序（この順で1行ずつ回答する）：

1. 判型 … `A5` または `B6`（表記そのまま。小文字は不可）
2. 裁ち落とし … `あり` または `なし`
3. ノンブル … `あり` または `なし`
4. ノンブル開始ページ（例: `001`）… **ノンブル「あり」の場合のみ**
5. スキップするページ（例: `001.024.059`、なければ空行）… 同上
6. 強制白抜きページ（例: `005.010`、なければ空行）… 同上
7. 余白の追加 … `y`（余白なし画像）または `n`（余白あり画像）

**ノンブル「なし」の場合は4〜6の行を入れない**（4行だけ流す）：

```bash
printf 'A5\nなし\nなし\ny\n' | python3 ~/my-workspace/manga_pdf_maker.py "/path/to/folder"
```

出力PDFはフォルダの**親ディレクトリ**に `KDP_<判型>_<裁ち落とし>...pdf` の名前で保存される。実行後にそのパスをユーザーに伝える。

ステップ3で「cover」トリミングを採用すると決めた場合は、上記の標準スクリプトではなく、ステップ3-3で用意した一時スクリプト（`scale = max(...)` に直したもの）を同じ引数・同じ質問順で実行する。標準スクリプトと一時スクリプトを混在させたり、生成済みPDFを後からトリミングしたりしない。

## 注意事項

- `manga_pdf_maker.py` が見つからない場合は `install.sh` を再実行するよう伝える
- PNGファイルは 001.png、002.png のように連番にする必要がある
- スキップページ・白抜きページはファイル名（拡張子なし）をドット区切りで指定する
- 暗いページのノンブルは自動で白抜きになる（ページ全体の平均明度ではなく、ノンブルが乗る位置周辺の局所明度で判定する）

## 完了後チェック（アドボケート検証）

出力PDFのパスをユーザーに伝える前に、以下を確認する。

- [ ] 選んだ判型（A5/B6）が正しくPDFに反映されているか（ステップ2の回答と出力ファイル名の`KDP_<判型>_...`が一致しているか）
- [ ] 「裁ち落としあり」を選んだ場合、入力PNGが本当に塗り足し（3mm）付きテンプレートで作られたものか一言確認する（塗り足しなしの画像に裁ち落とし処理をすると意図しない切れ方をする）
- [ ] ノンブル「あり」の場合、指定したスキップページ・強制白抜きページが正しく反映されているか（ページ数がPNG連番の数と一致しているか）
- [ ] 出力PDFの総ページ数が入力PNGファイル数と一致しているか
- [ ] ステップ3で白フチが検出されていた場合、採用した方式（cover / 個別修正 / 許容）通りに仕上がっているか、該当ページを画像化して四辺を確認する
- [ ] トリミングを行った場合、ノンブルが上下端で切れていない・トリム線に寄りすぎていないかを画像化して目視確認する

不一致や不安な点があれば、パスを伝える前にユーザーに一言添える（例：「◯ページ目、白抜き指定が反映されているか念のためご確認ください」）。

## フォルダパスがわからない場合

**Mac:** Finderでフォルダを右クリックし、**Optionキーを押しながら**「パス名をコピー」を選ぶ。

**Windows:** エクスプローラーでフォルダを**Shiftキーを押しながら右クリック**し、「パスのコピー」を選ぶ。

コピーしたパスをチャットに貼り付けてもらう。
