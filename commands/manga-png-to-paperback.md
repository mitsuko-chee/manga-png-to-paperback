CanvaなどでエクスポートしたPNGファイルを、Kindle KDP入稿用のPDFに変換する。

## 実行方法

すべての質問を **AskUserQuestion（選択式ダイアログ）** で行う。テキストで聞かない。
**裁ち落とし・余白追加の要否そのものはユーザーへの質問で決める（画像のピクセル内容を見て自動判定しない）。** ページ端の1pxノイズ等を絵と誤認しやすく、判定にも時間がかかるため。ただし、決定した判型・裁ち落としに対して画像の**サイズ（px、縦横比）**が合っているかどうかの単純な比較（ステップ4）は行う。これは中身を見るのではなく寸法を比較するだけなので誤判定の心配がなく、ノンブルを付ける前に白フチの有無を確定させるために必要。

### ステップ1：フォルダパスを確認する
AskUserQuestion でフォルダパスを聞く。

### ステップ2：基本設定をまとめて聞く
以下の3つを1回のAskUserQuestionで聞く：
- 判型（A5 / B6）
- 裁ち落とし（あり / なし）
- ノンブル（あり / なし）

**「裁ち落とし：あり」を選んだ場合、以下の警告をテキストで表示する：**
> ⚠️ 注意：「裁ち落としあり」は塗り足し（3mm）付きのテンプレートで作った画像専用です。

### ステップ3：余白の追加

**「裁ち落とし：あり」を選んだ場合はここを聞かない。** 裁ち落としありは絵がページ端（トリム線）まで届くフルブリード想定であり、そこに自動で10mmの余白を追加すると絵が内側に後退して矛盾するため、余白追加は自動的に「なし」として次に進む。

**「裁ち落とし：なし」を選んだ場合のみ**、AskUserQuestionで聞く：
- 追加する — 画像に余白がなく、絵が端に寄っている場合（10mmの余白をスクリプトが自動挿入）
- 追加しない — 画像にすでに余白がデザインされている場合

### ステップ4：白フチのチェック（画像サイズの比較のみ・ページ内容は見ない）

**この判断は必ずノンブルを追加する前に済ませる。** ノンブルの表示位置は塗り足し（トリム線）からの固定距離で決まるため、ノンブルを入れた後にページをトリミングすると、ノンブルがKDPの規定マージンより外側（トリム線に近すぎる位置）にはみ出し、入稿審査に通らない恐れがある。順序は **トリミング方式の確定 → ノンブル追加** を厳守する。

**画像の中身（ピクセル）は解析しない。** ファイルの幅・高さ（px）だけを見て、判型（裁ち落としを選んだ場合は塗り足し込み）の縦横比と比較する単純な計算に留める。中身を見て余白を推定する自動判定は行わない（1pxのノイズ線を絵と誤認した実績があるため）。

0. まず全PNGファイルの画像サイズ（px）を1回のPythonループで自動取得する（数百枚でも一瞬なので、ユーザーに確認は取らない）。ユニークな(幅,高さ)の組み合わせと、それぞれの縦横比を控えておく。
1. 控えておいた縦横比と、判型（裁ち落としありなら塗り足し込み）のページ縦横比を比較する。縦横比が全ファイルで揃っていれば通常通り進める。縦横比が異なるサイズグループが実際にある場合だけ、その旨を一言報告し、グループごとに計算する（解像度だけ違って縦横比が同じ場合は何も報告せず1つの計算のまま進める）。
2. ズレがあり、はみ出さない方向（contain）で縮小すると白いフチが出ると分かった場合：
   a. まず実際の白フチの大きさ（mm換算、片側あたり）をテキストで一言報告する（例:「左右に約1.0mmずつ白フチが出る可能性があります」）。scale_w = page_w/img_w, scale_h = page_h/img_h を計算し、小さい方が制約辺、余った側の (page辺 - scaled辺) がフチ幅。
   b. AskUserQuestionで3択を提示する。フチが片側1mm未満ならKDPの断裁誤差でほぼ吸収される可能性が高いため「このまま進める（contain）」を1番目（推奨）にする。片側1mm以上なら「拡大トリミング（cover）に切り替える」を1番目（推奨）にする：
      - 「このまま進める（contain）」— 誤差が断裁誤差許容内に収まりそうな場合
      - 「全ページ一括で拡大トリミング（cover）に切り替える」— フチが目立つ場合
      - 「特定ページのみ直す」— 選ばれたら、どのページ番号かをこの後のチャットで確認し、該当ページだけ個別に画像を編集する（一括のscale変更はしない）
3. トリミング（cover）を採用する場合は `manga_pdf_maker.py` 本体は書き換えず、スクラッチパッドにコピーして該当箇所（余白なし分岐の `scale = min(...)` を `scale = max(...)`）だけを直した一時スクリプトを用意する。ページサイズ（判型＋裁ち落とし）は変えず、画像側だけ拡大してはみ出しをトリミングする。
4. この時点でトリミング方式を確定させてから、ステップ5に進んでノンブルを含めた最終生成を行う（画像とノンブルは常に同じスクリプト実行の中で一緒に生成し、完成後のPDFを後から crop するようなことはしない）。

### ステップ5：ノンブル開始ページ・非表示ページ（ノンブルありの場合のみ）
以下の2つを1回のAskUserQuestionで聞く：
- 1ページ目をどの画像から始めるか（ファイル名の数字部分、例: 001）。**指定した画像が印字上の「1」になる**（印字される番号は常にそこから1,2,3…と連番になり、ファイル名の数字とは無関係。例えば「005」を指定しても005.pngに印字されるのは「5」ではなく「1」）
- ノンブルを表示させたくないページ（表紙・扉・章扉など。ドット区切り、例: 001.024.059。なければ「なし」）※内部的には「スキップページ」と呼ぶ機能だが、ユーザーには「スキップ」ではなく必ず「ノンブルを表示させたくないページ」と聞く（「スキップ」は誤解を招く表現のため使わない）

**強制白抜きページはこの時点では聞かない。** どのページが自動判定で白抜きミスしそうかは、実物のPDFを見るまで正確に決められないため。まず強制白抜きなし（自動の局所明度判定のみ）で生成し、完了後チェックで実際の出力を見てから、ユーザーの追加指示を受けて必要なら再生成する（詳細は完了後チェック参照）。なお「ノンブルを表示させたくないページ」もここで聞いた後、目視して追加に気づくことがあるため、完了後チェックでも重ねて確認する。

### ステップ6：スクリプトを実行する

スクリプトは対話式（`input()`で質問してくる）なので、**そのまま実行するとハングする**。
フォルダパスは第1引数で渡し、質問への回答は集めた内容から **printf で stdin に流し込む**：

```bash
printf '<判型>\n<裁ち落とし>\n<ノンブル>\n<開始ページ>\n<スキップ>\n<白抜き>\n<余白y/n>\n' \
  | python3 ~/my-workspace/manga_pdf_maker.py "<フォルダの絶対パス>"
```

質問の順序（この順で1行ずつ回答する）：

1. 判型 … `A5` または `B6`（表記そのまま。小文字は不可）
2. 裁ち落とし … `あり` または `なし`
3. ノンブル … `あり` または `なし`
4. ノンブル開始ページ（例: `001`）… **ノンブル「あり」の場合のみ**
5. ノンブルを表示させたくないページ（例: `001.024.059`、なければ空行）… 同上。ステップ5で聞いた内容を入れる
6. 強制白抜きページ（例: `005.010`、なければ空行）… 同上。**初回生成は空行のまま実行する**（完了後チェックで追加指示があれば、その時点でここに入れて再実行する）
7. 余白の追加 … `y`（追加する）または `n`（追加しない／裁ち落としありの場合は常にn）

**ノンブル「なし」の場合は4〜6の行を入れない**（4行だけ流す）：

```bash
printf 'A5\nなし\nなし\ny\n' | python3 ~/my-workspace/manga_pdf_maker.py "/path/to/folder"
```

出力PDFはフォルダの**親ディレクトリ**に `KDP_<判型>_<裁ち落とし>...pdf` の名前で保存される。実行後にそのパスをユーザーに伝える。

ステップ4で「cover」トリミングを採用すると決めた場合は、上記の標準スクリプトではなく、ステップ4-3で用意した一時スクリプト（`scale = max(...)` に直したもの）を同じ引数・同じ質問順で実行する。標準スクリプトと一時スクリプトを混在させたり、生成済みPDFを後からトリミングしたりしない。

## 注意事項

- `manga_pdf_maker.py` が見つからない場合は `install.sh` を再実行するよう伝える
- PNGファイルは 001.png、002.png のように連番にする必要がある
- ノンブルを表示させたくないページ・白抜きページはファイル名（拡張子なし）をドット区切りで指定する
- 暗いページのノンブルは自動で白抜きになる（ページ全体の平均明度ではなく、ノンブルが乗る位置周辺の局所明度で判定する）

## 完了後チェック（アドボケート検証）

スクリプトの実行が終わったら、検証結果を伝える前にまず「できました。検証に入ります」など一言だけ状況をテキストで伝える（無言で検証を続けない。ユーザーが待てるように、今何をしているかの一言を挟む）。

その後、出力PDFのパスをユーザーに伝える前に、以下を確認する。**検証は下記チェック項目をまとめて1回で行い、細切れに何度も検証を繰り返さない**（ページ数一致・判型サイズ・ノンブル反映等は1つのPythonスクリプトにまとめる。目視確認も対象を絞って一括で見る。詳細は本セクション末尾を参照）。

- [ ] 選んだ判型（A5/B6）が正しくPDFに反映されているか（ステップ2の回答と出力ファイル名の`KDP_<判型>_...`が一致しているか）
- [ ] 「裁ち落としあり」を選んだ場合、入力PNGが本当に塗り足し（3mm）付きテンプレートで作られたものか一言確認する（塗り足しなしの画像に裁ち落とし処理をすると意図しない切れ方をする）
- [ ] 出力PDFの総ページ数が入力PNGファイル数と一致しているか
- [ ] ステップ4で白フチが検出されていた場合、採用した方式（cover / 個別修正 / 許容）通りに仕上がっているか、該当ページを画像化して四辺を確認する
- [ ] トリミングを行った場合、ノンブルが上下端で切れていない・トリム線に寄りすぎていないかを画像化して目視確認する
- [ ] ステップ4で縦横比が異なるサイズグループが実際にあった場合のみ、合計1〜2枚の目視確認対象にそのグループの1枚を含める（縦横比が同じ解像度違いだけなら枚数を増やさない）

不一致や不安な点があれば、パスを伝える前にユーザーに一言添える（例：「◯ページ目、白抜き指定が反映されているか念のためご確認ください」）。

### 完成後の「修正したい箇所はありますか？」確認

上記チェックが済んだら、出力PDFのパスを伝えると同時に必ず「修正したい箇所はありますか？」と一言添える（狭く「ノンブルを表示させたくないページは？」「白抜きページは？」のように個別に聞かない。ステップ5で答えた「ノンブルを表示させたくないページ」への追加、白抜き判定が期待と違うページ、その他気づいた点をまとめて拾うための、あえて広い聞き方にする。ユーザーは初回は速さ優先で細かい指定を省略・見落としがちなので、実物を見てから思い出す前提で聞く）。

ユーザーから指定があった場合：
1. 「ノンブルを表示させたくないページ」の追加分・強制白抜き指定として整理する（ステップ5で既に答えている分があれば、それに追加する形でまとめる）。両方にまたがるファイル名がないか確認する（ノンブルを表示させたくないページに指定されたページはノンブル自体が描画されないため、白抜き指定をしても無効になる）。重複があれば強制白抜きリストから外し、「◯◯は非表示指定と重なっていたため白抜き指定から外しました」と伝える。
2. ステップ6の printf コマンドの該当行（ノンブルを表示させたくないページ／強制白抜き）だけを更新し、他の回答はそのまま**同じ設定で再実行**する（判型・裁ち落とし・開始ページ等を聞き直さない）。
3. 再実行後は出力PDFが上書きされるので、そのパスを改めて伝え、再度「修正したい箇所はありますか？」と確認する（解消するまで繰り返す）。ページ数一致等も再度確認する。

指定がなければそのまま完了とする。

**検証は1回のPythonスクリプトにまとめて実行する。** ページ数一致・判型サイズ・ノンブルのスキップ/白抜き反映（テキスト抽出で判定可能）は、Pythonプロセスを都度立ち上げ直さず、1つのスクリプト内でまとめて確認する。画像化して目視確認するのは、白フチ・ノンブルの位置関係など「実際に見ないと判断できない」項目に限定し、合計1〜2ページ程度に絞る（Readツールでの画像読み込みも同数に抑える）。細切れの検証を繰り返すと応答が遅くなる。

## フォルダパスがわからない場合

**Mac:** Finderでフォルダを右クリックし、**Optionキーを押しながら**「パス名をコピー」を選ぶ。

**Windows:** エクスプローラーでフォルダを**Shiftキーを押しながら右クリック**し、「パスのコピー」を選ぶ。

コピーしたパスをチャットに貼り付けてもらう。
